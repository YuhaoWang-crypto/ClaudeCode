Computational design report · Modal · Evo2 · AlphaGenome

Designing promoters that switch on only for the right signal, in the right cell

A working, self-hosted pipeline that pairs a DNA language model with a cell-type expression model to search for synthetic promoters — demonstrated on an interferon-γ sensor targeted to THP-1 monocytes.

Fixed IFN-γ enhancer (GAS) → Evo2 writes the designable region → AlphaGenome scores expression in THP-1 vs 5 off-target cells → MCMC keeps the best. All three models run on your Modal GPUs.

What runs today

Infrastructure — installed & cached on Modal

proto-tools (the evodesign execution layer) plus the Evo2 and AlphaGenome runtimes were built from source on Modal and cached in a persistent Volume, so runs after the first are fast. No PROTO_API_KEY — everything is self-hosted via HuggingFace weights.

Engineering journey

Nine real blockers cleared to self-host the stack

Neither model ships a turnkey runtime. Each of these was a distinct build or runtime failure diagnosed and fixed against the live Modal environment.

CUDA 13.3 → 12.4
micromamba pulled an unpinned toolkit; flash-attn/torch 2.6 need 12.x.
uv cache on Volume (EPERM) ×2
Modal Volumes can't persist uv temp files — moved cache to local disk, copy link-mode. Hit in both Evo2 and AlphaGenome setup.
torch index cu128 → cu124
driver-derived index lacked torch==2.6.0; forced the cu124 wheel index.
FP8 GPU capability
Evo2's transformer-engine FP8 needs compute ≥ 8.9; A100 is 8.0.
FP8 GEMM → BF16
FP8 cuBLASLt rejects short sequences; disabled FP8 → BF16 (same weights, runs on any GPU).
AlphaGenome 16,384-bp context
target must be embedded in a full model window; pad with neutral flanks.
Ontology term → CL:0001054
monocyte CL:0000576 has no RNA-seq track; mapped every cell to a verified AlphaGenome term.
Honest limitations & next steps

What this is — and isn't

Limitations

  • In-silico only. AlphaGenome scores are predictions — validate in a reporter assay (±IFN-γ luciferase, THP-1 vs control) before use.
  • Stimulus-response isn't optimized — it's guaranteed by the fixed GAS element (prior knowledge), not scored.
  • Small leverage. An 8-bp designable region barely moves a 16-kb prediction; margins are near zero.
  • Large search open. The 96-bp / long-generation run hit a persistent AlphaGenome input-validation quirk (Evo2 emits a non-ACGTN token) still being resolved.

Next steps

  • Enlarge the designable region and let enhancer spacing / minimal promoter be designed too — more specificity leverage.
  • Scale the search (more MCMC steps) once the long-generation sanitization is fixed.
  • Move to evo2_7b on H100 for stronger generation.
  • Reuse the same loop for other pairs — e.g. hypoxia × hepatocyte, or a digital stimulus-AND-cell-type gate.
