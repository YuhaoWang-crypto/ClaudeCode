# The official Virtual Cell Challenge 2026 panel

Everything before this document was a *reconstruction* of the challenge on
public data. This one is the challenge itself: the official validation bundle,
downloaded with the `vcc` CLI, run through the model that was built and
benchmarked before any of it was visible.

The headline is not a score. It is that **the atlas the whole project was built
on cannot answer a single question the challenge asks**, and what had to change.

---

## 1. What the challenge actually asks for

From `manifest.json` in the downloaded bundle, not from the marketing page:

| | |
|---|---|
| season / partition | 2026, `val`, panel `vcc2026-val-1` |
| contexts | A, B, C — anonymised, one `.h5ad` each |
| given per context | **18,400 non-targeting control cells**, 46 distinct NTC guide ids |
| withheld per context | 138,400 ground-truth cells |
| to predict | 300 knockdowns × 400 cells × 3 contexts = **360,000 cells** |
| gene axis | 18,533 symbols, fixed order |
| space | raw integer counts (`--require-counts` is the 2026 default) |

`vcc datasets list` offers exactly one dataset — `controls`. There is no
validation ground truth to download, so **nothing here can be scored locally
against the official answer**; scoring happens server-side on submission. That
constraint shapes the rest of this document: every number below comes from a
held-out benchmark on data whose truth *is* available, run through the identical
code path.

## 2. The contexts are not the four cell lines

The contexts are anonymised, and the model never uses their identity — it
conditions on the observed control profile. But knowing what they are tells you
how far the source data is being asked to reach. `python -m virtualcell.vcc2026
--identify` scores lineage marker panels on each context's control pseudobulk:

| lineage | A | B | C |
|---|---|---|---|
| T lymphoid (CD3E, CD3D, LCK, TRAC…) | **1.52** | 0.03 | 0.03 |
| epithelial, RPE-like (KRT8/18, CDH1, FOLR1, CLU) | 0.01 | **2.02** | 1.40 |
| squamous epithelial (KRT5, KRT13, KRT15, TACSTD2, CSTA) | 0.01 | 0.11 | **2.94** |
| mesenchymal (COL1A1/2, FN1, VIM) | 0.58 | **1.07** | 0.04 |
| erythroid / CML (HBG1/2, GATA1, KLF1, GYPA) | 0.00 | 0.00 | 0.00 |
| hepatocyte (ALB, APOA1, TTR, SERPINA1) | 0.00 | 0.00 | 0.00 |

Most distinctive genes per context, as excess over the other two:

- **A** — TRBC1 (+3.5), ARHGDIB (+3.1), CD1E (+2.8), LCP1 (+2.6), CD3D (+2.3)
- **B** — KRT7 (+3.2), COL5A1 (+3.1), CLU (+3.0), CDKN2A (+2.8), FOLR1 (+2.2)
- **C** — KRT15 (+3.0), FXYD3 (+3.0), KRT5 (+3.0), KRT13 (+2.8), TACSTD2 (+2.7)

So: **A is T-lymphoid, B is RPE-like epithelium, C is squamous/keratinocyte-like**,
and the three control profiles correlate with each other at only r = 0.61–0.74 in
log1p CP10K. Two consequences matter.

First, the source screen used below is **K562 — erythroid/CML — which scores 0.00
on all three contexts' lineage panels.** Every prediction is out-of-lineage
transfer, which is the hard case and the one the challenge is built to test.

Second, **context C resembles nothing in the four-line atlas.** K562, RPE1, HepG2
and Jurkat are erythroid, retinal-pigment epithelial, hepatocyte and T-cell; none
is squamous. Whatever the model does on C, it is not interpolating.

## 3. The atlas covers none of the panel

This is the finding that forced a rebuild.

| source screen | panel targets covered |
|---|---|
| K562 (essential panel) | **0 / 300** |
| RPE1 (essential panel) | **0 / 300** |
| HepG2 (essential panel) | **0 / 300** |
| Jurkat (essential panel) | **0 / 300** |
| K562 genome-wide (Replogle) | **272 / 300** |

Not a mapping bug — verified by spot check in both directions. RPL5, SF3B1 and
POLR2A are in the atlas and *not* in the official panel; ACLY, AGO1, AKT2, ADNP
and ABCD1 are in the panel and not in the atlas. The reason is structural:
Replogle's and Nadig's essential-gene arms target what a cell needs to *survive*,
which is exactly the set a challenge testing regulatory prediction would exclude.

A model built on the four-line atlas can therefore say nothing specific about any
of the 300 — it can only emit the average perturbation response, which *is* the
baseline the leaderboard normalises against. Its expected score is zero by
construction, and no amount of tuning changes that.

Replogle's **genome-wide K562 arm** (`K562_gwps_raw_bulk.h5ad`, 375 MB, already
downloaded) covers 272 of the 300, so it becomes the source.

### What the switch costs

| | four-line atlas | genome-wide K562 |
|---|---|---|
| source contexts | 4 | **1** |
| knockdowns | 2,053 shared | 9,866 |
| genes measured | 6,641 | 8,246 |
| official panel covered | 0 / 300 | 272 / 300 |
| official gene axis covered | 6,290 / 18,533 | 7,681 / 18,533 |

The expensive loss is **the cross-context averaging**, which the four-line
benchmark showed was worth having and which one source line cannot provide. What
survives is transfer, context modulation against the target's own baseline
expression, reliability shrinkage, and the on-target knockdown term.

The gene-axis loss is smaller than 7,681 / 18,533 = 41% suggests, because what is
missing is the long tail:

| context | share of total expression covered | share of the top 2,000 expressed genes |
|---|---|---|
| A | 86.4% | 93.1% |
| B | 81.9% | 86.6% |
| C | 79.8% | 83.9% |

Genes outside that set are predicted unchanged. So are 26 of the 28 uncovered
panel targets; the other two (HEATR6, TAF4) are measured genes, so they route
through the functional-neighbour path instead.

### The panel is weaker than the benchmark panel

Median L2 effect measured in K562: **3.16** for the 272 covered official targets,
**4.26** for the essential panel this project benchmarks on, **3.10** across all
9,866 screened knockdowns. Half the official panel sits below the genome-wide
median.

That matters because weak effects are where models differ most and where
discrimination is hardest, so a benchmark run on the essential panel would
overstate what to expect here. `virtualcell.vcc_eval --match-panel` resamples
knockdowns to the official panel's magnitude distribution for exactly this
reason.

## 4. Honest evaluation without the ground truth

Since the official truth is withheld, the model is scored where truth exists, in
the configuration a submission would actually use — one source line, out of
lineage:

```bash
python -m virtualcell.gwps --benchmark
```

Hold out RPE1, HepG2 and Jurkat one at a time. The only source is the genome-wide
K562 screen. Hyperparameters for each fold are tuned on the *other two* held-out
lines, so nothing selects on the line being scored. **K562 is never a target** —
the source screen is that same cell line, and scoring it would be reading back
the training data.

## 5. Building the submission

```bash
python -m virtualcell.vcc2026 --build
vcc prep /home/user/vcc_submission/prediction.h5ad \
  -g /home/user/vcc_official/gene_names.csv \
  --perts /home/user/vcc_official/pert_counts.csv -o prediction.vcc
```

Predicted effects are turned into cells by resampling that context's *real*
control cells and applying the predicted shift multiplicatively, with a per-cell
efficiency drawn around 1. This is not cosmetic: `cell-eval` runs its rank-sum DE
test on the submitted cells, so 400 identical copies of a predicted mean have zero
within-group variance and manufacture significance a prediction has not earned.
`virtualcell.vcc_eval` measures that gap directly.

### The validator runs out of memory before the submission runs out of spec

`vcc prep` holds the whole matrix as an in-memory CSR. At the density of real
control cells that is not survivable on a normal machine:

| slice | cells | stored values | peak RSS | result |
|---|---|---|---|---|
| structural probe | 7,200 | 41.5 M | — | ✅ passes |
| partial context | 40,000 | 238 M | **6.9 GB** | ✅ passes |
| one context | 120,000 | 715 M | **14.0 GB** | ❌ **SIGKILL** |
| full submission | 360,000 | 2,078 M | est. 40–60 GB | not attemptable here |

The file itself is within spec — the scorer's own cap is 4.75e9 stored values,
so submissions this size are expected. Only the local validator is out of
memory. Every check `prep` performs was therefore run directly against the file:

```
360,000 cells x 18,533 genes, 2,078,070,705 stored values
gene axis identical to the official gene_names.csv: True   (all unique: True)
context A: 120,000 cells, 300 distinct targets, 400 cells each,
           targets == official panel: True, control label present: False
context B: same — True
context C: same — True
```

`virtualcell.vcc_submit --split A --max-cells N` lifts a slice out by streaming
`indptr`, for validating on a machine that can hold one.

## 6. Can an external model supply what the source cannot?

The measurements bound this before any model is run. Cross-context effect
*shape* is nearly noise-limited — two runs of the same K562 screen agree at
r = 0.319 — and effect *magnitude* is already read off the source. What is
genuinely missing is anything about contexts A, B and C beyond their control
profiles, and in particular **how completely CRISPRi silences a target there**,
since no perturbation has ever been measured in them.

Three candidates, tested rather than argued about:

| model | has a cell-context input? | cis or trans | result |
|---|---|---|---|
| **Evo2** (DNA LM) | **no** | cis | not run — its score for a gene is identical in every context, so it cannot express a cross-context term at all |
| **frontier language model** | yes, and it uses it | conceptual | ❌ **loses to the context-free baseline** |
| **AlphaGenome** | yes — K562, HepG2, Jurkat, keratinocyte, T-cell | **cis** | ❌ **no signal on the one gap it could fill** |

### The language model differentiates strongly and is still wrong

`python -m virtualcell.llm_prior --prepare` / `--score`, on 24 knockdowns with
strong measured effects in both Jurkat and RPE1, cell lines **named** rather than
anonymised and the prompt asking explicitly for lineage-specific answers — the
most favourable conditions available.

| DE overlap@100 | Jurkat | RPE1 |
|---|---|---|
| global mean *(baseline)* | 0.1231 | 0.1379 |
| naive transfer | 0.2361 | 0.2175 |
| **ContextTransfer** | **0.2582** | **0.2265** |
| language model | 0.1047 | 0.0887 |

Blending its ranking into the model's is monotonically worse at every weight
from 0.1 to 1.0, so there is no complementary signal either. 70% of its named
symbols exist in the measured gene universe at all.

The intuitive diagnosis — *it gave a generic, context-blind answer* — is **false**.
Its two answers share only a quarter of their genes (Jaccard 0.248) and its
reasoning is explicitly lineage-aware, invoking T-cell identity genes and
Jurkat's inactive p53. It varies its answer confidently and in the wrong
direction, which is harder to exploit than indifference would have been. The
likely reason: a language model's knowledge is pathway-level causal narrative,
while measured pseudobulk DE is dominated by global state — growth rate,
ribosome content, stress response.

### AlphaGenome predicts expression across contexts, but not CRISPRi efficiency

150 genes with a measured on-target residual in all three lines, against
predicted promoter RNA-seq and DNase in the matching biosamples
(`EFO:0002067`, `EFO:0001187`, `CLO:0007045`):

| track | pair | n | Spearman |
|---|---|---|---|
| RNA-seq | K562/HepG2 | 150 | +0.114 (p 0.17) |
| RNA-seq | K562/Jurkat | 150 | −0.025 (p 0.76) |
| RNA-seq | HepG2/Jurkat | 150 | +0.052 (p 0.53) |
| DNase | K562/HepG2 | 150 | −0.001 (p 1.00) |
| DNase | K562/Jurkat | 150 | +0.007 (p 0.93) |
| DNase | HepG2/Jurkat | 150 | +0.028 (p 0.73) |

**Positive control**, same predictions against measured *control expression*
ratios: +0.230 (p 0.005), +0.160 (p 0.051), +0.288 (p 0.0003). And the quantity
being predicted really does vary: median |log2 ratio| of the measured on-target
residual between contexts is **0.83**, about 1.8× typical.

So the pipeline works, the target varies, and the signal is absent. Read the
power honestly: the control shows the test can detect ρ ≈ 0.23, so it rules out
an on-target effect of that size, not an arbitrarily small one.

All three failures share a cause, and it is not that the models are weak.
**What they can contribute about a context is already measured here, from 18,400
real control cells; what they cannot contribute is trans causal structure, which
is the entire task.**

## 7. What this does and does not establish

**Established.** The official bundle has been downloaded and parsed; the panel's
coverage gap has been measured, not guessed; a source that covers 91% of the
panel has been substituted; the resulting single-source configuration has been
benchmarked out-of-lineage on real held-out data with leak-free tuning; the
effect scale has been chosen under the metric threshold the challenge enforces
rather than the aggregate a tuner prefers; a well-formed submission has been
produced and verified against every criterion the official validator checks; and
three external-model routes have been tested and measured rather than assumed.

**Not established.** No score against the official ground truth, which is
withheld and only obtainable by submitting. The three contexts are transcriptomic
strangers to the source screen, and a benchmark on RPE1/HepG2/Jurkat is the
closest available proxy, not a substitute. The full submission has not been
through `vcc prep` itself, for the memory reason above.
