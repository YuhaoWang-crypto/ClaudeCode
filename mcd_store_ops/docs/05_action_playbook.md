# 05 · 行动卡：红灯亮了做什么

`config/metrics.json` 里每个指标都挂了一个 `playbook` 编号。
看板上红灯亮起时，显示的不只是数字，还有这张卡的编号——
因为**看板的终点不是"知道了"，是"做什么"**。

每张卡的结构固定：先判断根因（不同根因动作完全不同），再给动作，最后给验证方式。
诊断这一步不能省——同一个红灯，根因不同则动作相反，猜错了比不做还糟。

---

## PB-01 · 销售 / 客流不达标

**先分清是"人少"还是"人均少"**（看 `guest_count` 和 `avg_check` 哪个先塌）：

| 根因 | 判断依据 | 动作 |
|---|---|---|
| 客流少 | GC 跌、客单持平 | 查外部：天气 / 周边施工 / 竞品活动 / 平台曝光掉了；查内部：外送是否被限流、点餐机是否有故障 |
| 客单少 | GC 持平、客单跌 | 走 PB-02（附加销售）；查活动结构是否换了低价档 |
| 两个都跌 | — | 先看是不是全时段跌。单时段跌 → 该时段有具体事件；全时段跌 → 商圈或平台层面的事 |

**下钻顺序**：时段 → 渠道 → 品类。
先定位到时段，因为时段对应排班和备货，是店长唯一能当天调整的东西。

**验证**：次日同时段同渠道回到预测的 ±3% 以内。

---

## PB-02 · 客单价 / 附加销售不足

**根因判断**：

- 附加销售率在人工点单渠道低、点餐机正常 → **人的问题**（话术、动员、忙起来就忘）
- 两个渠道都低 → **产品/活动结构问题**，上报，不是店长能当天解决的
- 高峰时段明显低于平峰 → **产能挤压**（忙到顾不上推荐），这其实是速度问题，走 PB-04

**动作**（针对人的问题）：

1. 拉 `upsell_rate × cashier_id` 归因矩阵，找出后 30% 的收银员
2. 班前会指定当日主推 1 个品（只推一个，推三个等于不推）
3. 训练员跟班 2 小时现场纠正话术

**验证**：三天内后 30% 的人追上门店均值的 80%。

---

## PB-03 · 外送时效 / 评分下滑

外送和堂食是两套流程，**用堂食的办法救外送通常无效**。

**根因判断**（拉 `delivery_handover_time × daypart` 交叉矩阵）：

| 现象 | 根因 | 动作 |
|---|---|---|
| 全时段都慢 | 流程问题：打包工位与堂食抢人、备料位置远 | 重设计打包动线；固定一个打包位不参与堂食（这需要跨部门，走 Q2 上报） |
| 只有高峰慢 | 产能问题 | 高峰给外送单独留人；调整平台接单上限 |
| 某个平台慢 | 平台侧：骑手调度、门店在平台的排单权重 | 联系平台商务；检查出餐时间设置是否合理 |
| 差评集中在"漏餐" | 核对环节缺失 | 上双人核对 + 封签；差错清单每日复盘 |

**注意**：评分是**滞后指标**，今天的动作要一到两周才反映在分上。
不要按评分的日波动做决策，按 `delivery_handover_time` 和 `issue_flag` 做决策。

**验证**：出餐时长回到目标线以内连续 3 天，之后看评分是否跟上。

## PB-04 · 服务速度不达标

**这是最需要先诊断再动手的一张卡。** 直接"加人"是最常见也最贵的错误答案。

**第一步：分段定位**（得来速有天然的分段计时，其他渠道用 KDS）

| 慢在哪一段 | 说明 | 动作 |
|---|---|---|
| 点单段长 | 点单员不熟 / 菜单复杂 / 顾客犹豫 | 加点单员或开第二车道；训练；高峰前把促销话术统一 |
| 排队段长 | 前面堵住了，本身不是问题，是**结果** | 往下看下一段 |
| 取餐窗 / 出餐段长 | **后厨备餐没跟上** ← 最常见的真根因 | 加人到理货和出品，不是加到点单 |
| 制作段长 | 设备故障 / 备货批量太小 / 新手站岗 | 查设备工单；调整批量；换认证员工 |

**第二步：分清结构问题还是产能问题**（拉时段 × 渠道交叉矩阵）

- **某渠道全时段红** → 结构问题，加人无效，要改流程
- **某时段所有渠道红** → 产能问题，排班能解决

**第三步：确认是不是连片**（时段矩阵）
连续 2 个以上 15 分钟才算问题，单点飘红是噪声，别为它调排班。

**验证**：目标时段的达标率回到绿线以上，且 SPLH 没有明显下降
（如果达标率上去了但 SPLH 掉了，说明是靠堆人换的，不可持续）。

## PB-05 · 订单差错 / 投诉上升

**先看是不是同一件事在重复发生**（按 `issue_type` 做归因矩阵）：

- 集中在**一种差错类型** → 流程缺陷，改流程（例：漏餐 → 上核对清单和封签）
- 集中在**一个时段** → 产能问题，走 PB-04
- 集中在**一个渠道** → 该渠道的交接环节，通常是打包或叫号
- 分散无规律 → 训练问题，看 `station_certification`

**一周内同一个 `comment_tag` 出现 3 次以上**，它就不是个案，
必须进周复盘并指定改进负责人——这是把"偶发"转成"系统性问题"的判定线。

**验证**：千单投诉数连续 5 天在绿线内，且同类差错不再出现在 top 3。

---

## PB-06 · 废弃 / 食品成本超标

**先分清废弃的类型**（`waste_type` 三类，动作完全不同）：

| 类型 | 含义 | 根因 | 动作 |
|---|---|---|---|
| `complete` 成品废弃 | 做出来没卖掉 | 备货节奏问题（批量太大 / 预测偏高） | 减小批量、缩短备货提前量；核对预测偏差 |
| `raw` 原料废弃 | 过期、掉落、变质 | 先进先出没做 / 订货量过大 | 查 FIFO 执行；调订货量；查冷链 |
| `holding` 保温超时 | 保温柜里超时被丢 | 备货节奏 + 高峰预判失误 | 高峰前按预测分批做，不要一次做满 |

**食品成本率高但废弃正常** → 问题在盘点差异（`variance_cost`），
根因通常是配方/打料不标准、收货短少、或者废弃**漏登记**。
连续三天差异同向，就该查这三件事，而不是继续压废弃。

**验证**：次日同时段废弃回到绿线；一周后 FC% 跟上。

## PB-07 · 人工成本 / 排班效率

**先看 SPLH 和速度的组合**，这是判断根因的关键：

| SPLH | 速度 | 诊断 | 动作 |
|---|---|---|---|
| 低 | 差 | **排班结构错**——不是人不够，是人站错岗 | 调岗位配置，不要加人头 |
| 低 | 好 | 人排多了 | 削减平峰工时，保住高峰 |
| 高 | 差 | 人排少了 | 高峰加人；这是真正需要加人的唯一情况 |
| 高 | 好 | 健康 | 记录这天的排班曲线，作为模板 |

**出勤和迟到**是另一条线：排班对了但人没到，等于没排。
迟到集中在某个时段（比如早班）→ 通常是通勤或交接问题，不是态度问题，
跟当事人谈之前先看时段矩阵。

**验证**：目标时段 SPLH 回到绿线，且速度达标率不下降。

---

## PB-08 · 现金短溢

金额通常很小，但**性质是内控问题，不是成本问题**，不能按金额大小排优先级。

1. 定位到班次和收银员（`cash_over_short × shift / cashier_id`）
2. 复核当班交接记录与监控
3. **当天闭环，不隔夜**——隔夜之后记忆和证据都不可靠了
4. 同一人连续出现 → 转人事流程，不再是营运问题

## PB-09 · 食安检查失分 / 温度异常

**这张卡没有"先记着"这个选项。**

| 情况 | 动作 |
|---|---|
| 关键项 fail | **立即停止该产品出品**，整改后复检通过才恢复 |
| 温度超标 | 判断受影响的批次范围 → 按标准处置（丢弃/降级）→ 报修设备 → 加密监测频次 |
| 冷藏/冷冻库超标 | 按超标时长和幅度评估库内所有物料；这是可能触发全库处置的情况 |
| 一般项 fail | 当班整改，记录整改人和复检时间 |

**同一检查项一周内 fail 两次**，就不是执行问题，是流程或设备问题，必须上报。

**验证**：复检通过 + 连续 3 天该项无 fail。

---

## PB-10 · 清洁 / 巡店失分

顾客对"干净"的判断发生在**洗手间和餐桌**，不在厨房。
所以分区打分（`cleanliness_score × zone`）比总分有用得多——
总分 92 分可能是"厨房 98、洗手间 78"，而顾客只看到 78 那个。

- 洗手间失分 → 提高巡检频次（高峰期每小时一次），这是投入产出比最高的一项
- 大堂失分 → 高峰收餐人力不足，走 PB-07
- 外围/车道失分 → 通常是排班里根本没有这个岗位

---

## PB-11 · 设备停机

1. 判断是否**停售**：关键设备停机要立刻决定哪些产品下架，并同步到所有点单渠道
   （尤其别忘了外送平台——平台上还在卖但门店做不出来，是差评的最大来源之一）
2. 报修并记录 `downtime_minutes`
3. 同一设备一个月内两次故障 → 走更换评估，不再继续修

**预防**：`pm_cycle_days` 到期未保养的设备，故障率显著更高。
周会看一次保养到期清单，比事后修便宜得多。

---

## PB-12 · 人员流失 / 认证覆盖不足

这是**唯一一张不看日数据的卡**——日维度上这两个指标全是噪声。

- **30 日流失率**：按 `tenure_band` 下钻。
  流失集中在 `<90天` → 入职培训和排班体验的问题（新人被丢在高峰上是最常见的原因）；
  流失分布在 `>1年` → 发展通道或薪酬的问题，超出门店范围，上报。
- **岗位认证覆盖率**：按 `station` 下钻。
  某个岗位覆盖率长期低（例：炸炉、外送打包）→ 训练排期没有覆盖到它，
  而这个岗位往往正是速度和废弃问题的源头。

**这两个指标是一切的上游。** 速度、废弃、食安、差错的红灯，
追到最后有相当一部分落在"当班的人没认证"或"老手刚走了三个"上。
所以它们虽然不在日报的三件事里，却必须在周会的第一页。
