# 扩到 ISPY2：标签侧成了，影像侧卡住了

目标是把监督实验的影像侧从 91 例扩到几百例。**结果是一半成功、一半明确失败**，
失败的那一半有具体原因和具体解法，写在下面。

先纠正我自己上一轮的一句话：我说过"ISPY2 全部 719 例都有分割"。
那是基于 TCIA 上 `SEG` modality 存在得出的，**在关键意义上是错的**——
那些 SEG 不是肿瘤分割。详见第 2 节。

---

## 1. 标签侧：717 例，成了

| 项 | 值 |
|---|---|
| TCIA `ispy2` 有 MRI 的患者 | 719 |
| GSE194040 治疗前表达谱样本 | 988 |
| **可连接的患者** | **717** |
| 中心数 | I-SPY2 TRIAL 约 20 家美国中心 |

**ID 对齐是核实过的**：基因水平表达矩阵的列头（如 `756412`）一度看起来像另一套研究编号，
但与 GEO 的 `patient id` 名单比对，**986/988 重合**——列头就是 patient id，只是顺序不同。
而 TCIA 的 `ISPY2-100899` 与 GEO 的 `patient id: 100899` 直接对应。

29 个免疫签名基因全部找到，一致性检查通过：

| 检查 | 值 | 期望 |
|---|---|---|
| corr(CD8 核心, TIS) | **+0.941** | 应该很高 ✅ |
| corr(CD8 核心, EPCAM 上皮对照) | **−0.155** | 应该接近 0 或为负 ✅ |

结果在 `results/ispy2_immune_scores.json`，717 例 × 4 个签名分数，可直接使用。

**但标签类型变了，这是一个损失，必须写出来**：ISPY2 没有公开的 H&E 全切片，
所以 Saltz TIL 图谱、几何描述子、沙漠/排斥/炎症三分类**在 ISPY2 上都不存在**。
剩下的是治疗前活检的 bulk 转录组，它只支持 `inflamed_vs_rest` 这一个对比——
这正是 `labels/schema.py` 从一开始就写死的那条约束，现在在实践中兑现了。

## 2. 影像侧：ISPY2 的 SEG 不是肿瘤分割

TCIA 上 ISPY2 有 2,688 个 `SEG` 序列，覆盖全部 719 例。看起来像是分割问题解决了。
**不是。**

逐条证据：

| 检查 | 结果 |
|---|---|
| DICOM SegmentSequence 标签 | `VOLSER Analysis Mask` |
| SegmentedPropertyType | **Breast**（不是 Neoplasm） |
| DerivationDescription | `VOLSER,BACKGROUND=475,SER PE THRESHOLD=70` |
| 掩膜体积 | 中位 **4,235 cm³**（乳腺量级，不是肿瘤量级） |
| 是否有肿瘤形状的位平面 | **没有**（见下） |

掩膜是 uint8 位标志编码，四个位平面的几何：

| 位 | 体积 | 连通块数 | 最大块占比 | 判读 |
|---|---|---|---|---|
| bit 0 | ~4,600 cm³ | 29 | 1.00 | 整个裁剪体 |
| bit 1 | 2.7–29 cm³ | **1,300–18,000** | **0.00** | 散点体素标志 |
| bit 4 | ~4,330 cm³ | 305 | 1.00 | 整个裁剪体 |
| bit 5 | ~4,370 cm³ | 1 | 1.00 | 整个裁剪体 |

**没有一个位平面是肿瘤。** 它标记的是进入试验 FTV（功能性肿瘤体积）计算的乳腺区域和阈值标志。

### 两条推导路线，都试了，都不够好

**路线一：按试验自己的 FTV 定义推导** —— VOI 内 ∧ PE ≥ 70%，取最大连通块。

中位数 30.3 cm³ 与已发表的 I-SPY2 治疗前 FTV（约 25–30 cm³）吻合得很好。
**但 IQR 是 [5.3, 225.8]，最大 493 cm³。** 在背景实质强化明显的病例里，
肿瘤与实质连成一整块（最大块占比 0.90–0.95），提取出来的就是"整个乳腺"的特征。

这种失败是**静默的**——不会报错，只会污染那部分病例的全部特征。

**路线二：把 bit 1 当作试验算好的 FTV** —— 它与推导体积跨患者相关 **r=+0.855**，
方向对，但中位数只有 5.6 cm³，而且散成上千个不连通体素（最大块占比 0.00）。
在这样的 ROI 上算纹理矩阵没有意义。

### 顺带修掉的一个真 bug

多帧 DICOM（SEG）的几何重建原来是错的：`PlaneOrientationSequence` 在
**SharedFunctionalGroupsSequence** 里而不是 PerFrame 里，读不到就留了默认单位阵，
而 SER/PE 体积的方向余弦是 (−1, −1, 1)。两者原点相同、方向相反，
重采样后掩膜几乎完全落在目标网格之外——bit5 占比从 0.945 塌到 **1.5e-5**。

这个 bug 的可怕之处在于它**不报错**。修正后同时处理了三件事：从 Shared 读方向、
按切片法向排序帧、切片间距从帧位置反推而不是用 SliceThickness。
`mri_cd8_til/experiments/ispy2.py` 里有对应的测试。

## 3. 解法：需要你的 Synapse 凭据

**MAMA-MIA** 提供 1,506 例**专家复核过的肿瘤分割**（NIfTI），覆盖
ISPY1 / ISPY2 / Breast-MRI-NACT-Pilot / Duke 四个集合，正是需要的东西。

但它通过 Synapse 分发（`syn60868042`），需要账号和 Personal Access Token：

```bash
synapse login --authToken <YOUR_TOKEN>
synapse get -r syn60868042
```

本会话是非交互的，无法完成 OAuth 流程，也不应当索取令牌。
**这一步需要你在有凭据的环境里执行。**

拿到之后要做的事都已经就绪：`mri_cd8_til/experiments/ispy2.py` 里的
`load_case` 只需把 `voi` 换成 MAMA-MIA 的分割，
`imaging/roi.py` 的全瘤 / 内环 / 外环构建和 `features/extractor.py` 的提取器直接可用，
标签侧 717 例已经算好。

## 4. 现在的账

| | 规模 | 状态 |
|---|---|---|
| TCGA-BRCA：影像特征 + 空间 TIL 表型 | **91** | ✅ 已跑完（RM-whole 0.713 / RM-peri 0.440） |
| TCGA-BRCA：空间 TIL 表型（标签侧） | **136** | ✅ 已建好 |
| ISPY2：转录组免疫标签 | **717** | ✅ 已建好，一致性检查通过 |
| ISPY2：影像特征 | **0** | ❌ 卡在肿瘤分割，需 MAMA-MIA |

**如果 MAMA-MIA 到位**，监督队列会从 91 例变成约 700 例、约 20 个中心，
而多中心模拟预测这一步（182 → 900）单独就值 **+0.185 AUC**——
这是本项目量化过的、最大的单项杠杆。

代价也要说清：那 700 例的标签是转录组的，**只能验 RM-whole**；
RM-peri 仍然只能在 TCGA-BRCA 的 136 例上做。
