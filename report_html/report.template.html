34 个新抗原怎么选

从一个黑色素瘤外显子组的 388 个体细胞突变，到装进一条 mRNA 的 34 个位点。 难的从来不是生成候选肽，而是花掉那 34 个名额。

00

这个 skill 复现什么，不复现什么

公开信息定住了流程，没有定住打分。

intismeran autogene（原 mRNA-4157/V940）这一类产品，公开披露的是工作流： 肿瘤与正常组织 DNA 测序、肿瘤 RNA 表达、找体细胞突变、HLA 分型、算法预测呈递与识别、 最多选 34 个新抗原、编码进一条 LNP 递送的个体化 mRNA。 具体的评分公式、训练集、阈值和构建体设计规则是专有技术，没有被复现。

这里做的是：把那一层用写死在代码里、可读可改、有文献出处的替代方案补上， 再配一个基准测试，让排序结果可以被检验，而不是只能被相信。

三种标签，贯穿全文

computed 这次运行里，真实预测器跑在真实数据上算出来的 · assumed 拿不到数据时的配置替代值 · unverified 没有实验确认的预测。 这条流水线做出的每一个免疫原性判断都是 unverified。

漏斗里最狠的一刀是表达：353 → 265，砍掉的 87 个突变落在肿瘤 RNA 里读不到的基因上。 这一步是硬门控而不是打分项——一个在 0 TPM 基因上的完美结合肽，不管 NetMHCpan 给多少分， 它都不会变成一个真实的肽。

4 个突变没能变成肽，原因被逐条写出来而不是悄悄丢掉：参考蛋白组在该位点的氨基酸与变异记录不符（同工型不一致）。 移码突变需要转录本级别的核苷酸注释才能翻译出新读框，这类变异同样会被列出来，而不是假装不存在。

铺开是一次对冲：肿瘤丢掉一个 HLA 等位基因是有文献记载的免疫逃逸路线，不该让整条疫苗因此哑掉。

这一批的两个软肋 assumed

  • HLA 分型是假设的。TCGA 的 HLA 调用是受控访问数据，公开接口拿不到。 demo 用了一组常见单倍型。真实运行时换成患者正常样本的四位分型即可，其余代码一行不用改—— 但整条排序都继承这个假设，它是全流程最大的误差来源。
  • 克隆性不可信。纯度被固定为 0.7、拷贝数一律当 2， 于是 34 个里只有 1 个 CCF ≥ 0.8。这更可能说明该样本真实纯度远低于 0.7， 而不是说明这些突变都是亚克隆的。真实运行需要 ABSOLUTE / FACETS 的纯度与片段级拷贝数。
04

接头表位：把 34 段接起来会凭空造出 33 段新序列

这是从"排序"走到"产品"时最容易安静出错的地方。

每个突变取一段 25-mer 小基因（突变居中），34 段首尾相接，就产生了 33 个接头。 每个接头处的那些跨界肽，在患者肿瘤里从来不存在。 如果其中某条恰好被患者的 HLA 强呈递，它就是一个诱饵表位： 和真表位抢同一批 HLA 分子、抢同一批 T 细胞，而且不具肿瘤特异性。

所以排序不是随便排的。流水线先算出一个 34×34 的接头代价矩阵 （把任意两段相邻时产生的跨界肽全部拿去做 HLA 预测）， 再用贪心 + 2-opt 求一条开放路径把总代价压到最低。

基准测试：一个不好看但重要的结果

先看它怎么骗人，再看它真正说了什么。

阳性样本怎么来：从 IEDB 拉出所有"人源抗原、I 类、人 T 细胞实验阳性"的表位， 只保留那些与人参考蛋白组的某个 k-mer 恰好差一个氨基酸、且自身不出现在蛋白组里的。 这个差异是"体细胞突变形状"的，而且顺手把野生型对照肽也一并交出来， 于是 agretopicity 可以按主流程一模一样的方式精确计算。最终得到 119 条。

诱饵是其他 TCGA 黑色素瘤患者的真实错义突变肽。 它们是未标注的，不是"已验证阴性"——所以所有 AUC 都是分离度的下界。

第一版基准是个陷阱 读作警告，不是成绩

只按等位基因和长度匹配诱饵时，NetMHCpan %rank 单独就拿到 AUC 0.966。 这不是流水线有效的证据。IEDB 里的表位当年大多正是因为结合力强才被发现的 （很多本来就是跑结合预测挑出来的），而随机突变肽大多不结合。 两组的主要差别就是结合力，任何结合预测器都能轻松分开，这跟免疫原性无关。 把这个数字拿去当成绩，量的是 NetMHCpan，不是自己的选择层。

所以做了第二版：只保留阳性数够多的 3 个等位基因，诱饵从 21,500 条的大池子里抽 （强结合肽在随机肽里本来就稀有——按 %rank 的定义，只有约 0.5% 的随机肽落在 0.5% 以下， 小池子里根本不存在结合力对得上的诱饵），再按预测 %rank 分层抽样， 让两类在每个结合力档位里的构成一致。

结论 unverified

控制住呈递之后，这里没有任何一个特征——包括加权综合分——能把已验证的免疫原性新表位 与未标注诱饵分开得比随机好多少。综合分甚至略低于结合预测器单独的表现。 按这份证据，这些肽内在特征没有挣到它们的权重，文献默认权重不能被说成是调好的模型。

这不否定流水线，但它把有效的部分指清楚了：真正在起作用的是 门控（表达、相对自身蛋白组的肿瘤特异性、克隆性）和 载荷约束（等位基因铺开、每基因上限、接头控制）—— 而这些恰恰是任何"肽内在特征"基准测不到的东西，且它们实实在在改变了最终是哪 34 个突变被做出来。

两个方向都要说清的注意事项：诱饵未标注（把 AUC 压低）；n = 86 偏小； 挖出来的阳性是个混合体——里面有真正的肿瘤新抗原，也有翻译后修饰的自身肽 （经典的酪氨酸酶 YMDGTMSQV 其实是 YMNGTMSQV 脱酰胺后的产物， 离自身只差一个残基、确实有 T 细胞反应，但不是体细胞突变）， 还有次要组织相容性抗原那类等位变异。 它们都满足"离自身一个替换且已证实有免疫原性"，所以不是噪声，但也不全是新抗原。

06

真实标签基准：TESLA

第 5 节的诱饵是"未标注"的，这里的阴性是做过实验、结果为阴的。

读者提供的另一个新抗原包里带了一份 TESLA 公开镜像： 522 个肽-HLA 组合、35 个经患者 T 细胞实验确认有免疫原性、6 位患者， 并附带若干已发表模型的预计算分数。 这正是我之前拿不到的东西——所以我直接把它接了进来（tesla.py）， 用完全相同的行去考所有模型。

阳性率只有 6.7%，此时准确率毫无意义，能动的是平均精确率（PR-AUC）和 每位患者的 top-N 命中数——后者才是"34 个名额"真正关心的。 野生型对照肽用与第 5 节相同的"离自身一个替换"检索还原，522 条里还原了 487 条。

两个结论，一个是好消息，一个不是

一个当代呈递预测器打败了这份镜像里每一个已发表的免疫原性模型。 NetMHCpan-4.1 EL 的 %rank 单独就有 AP 0.207、34 名额内命中 31/35； 最好的已发表列是 0.132、19/35。

它也打败了我自己的综合分。方向和第 5 节完全一致， 而这次是真实标签、真实阴性。两个独立数据集给出同一个结论，够我动手了： 默认权重已经改成呈递主导（0.30 → 0.45），agretopicity、非自身性、TCR 先验、 疏水性全部下调。这一改把综合分从 AP 0.149 提到 0.163、命中从 24 提到 26—— 有真实提升，但仍低于单独用呈递。

为什么不干脆只用呈递？因为综合分里还有表达量和克隆性—— TESLA 的一个肽既没有肿瘤 RNA 值也没有 CCF，这份数据根本评不了它们， 而它们描述的是肿瘤的事实，不是对 T 细胞的猜测。所以它们保留权重， 被证伪的是那几个肽内在特征。config.PRESENTATION_ONLY 作为预设一起发出去了，它在 TESLA 上分最高。

07

与另一个新抗原包的对比

两个包都跑了、都读了代码。对方更好的地方我改了。

一句话：对方的审计与治理层更好，而且带来了更好的真值数据； 这一包的计算更完整——它算出了对方要求用户自己填的那些特征， 也真的做了对方只输出了一个状态字符串的接头筛查。

我从它那里吸收的

  • TESLA 镜像（见上一节）。这是整个包里最有价值的东西。
  • 审计清单。它的 audit_manifest.json 记录输入 SHA-256、 工具版本、能力快照、生效权重、实际使用的预测器。我现在也写了 （provenance.py），并加上 git revision 和变异/预测/入选表的内容哈希。
  • 证据级别（E0/E2）。对"这个亲和力是谁算出来的"这个具体问题， 比笼统的 unverified 更锋利。我采纳为 E0–E3，但不实现 E0： 本包没有基于哈希的替身预测器，因为一个长得像亲和力的哈希值，早晚会被当成亲和力引用。
  • 它的护栏清单写得好——按患者而不是按肽切分评估、 类别不平衡时报 PR-AUC 和 top-N 而不是准确率、不把确定性哈希叫作 AI 预测。 tesla.evaluate 就是照这几条写的。

前两行最要紧。recognition_score 和 normal_similarity 是新抗原选择里最难的两个量；把它们当输入，等于把难题移交给了用户。 它自己的 demo 夹具里，这两列填的是夹具值。

没站住的几处（都对着代码核过，不是看文档）

  • 接头筛查写了但没实现。它的 SKILL.md 第 7 步说"用同一个真实 HLA 预测器筛查接头，否则标记为未解决"。build_construct() 里没有任何预测调用， 状态字符串是 "unresolved" if evidence=="E0" else "predictor_available_not_clinically_validated"。 装了真实预测器时报告显示后者，读起来像"筛过了"，实际只表示"存在一个预测器"。 参考量级：本包 demo 里优化之后仍有 38/1122 条跨界肽落在 0.5% rank 以内。
  • I 类和 II 类被 max() 合并了，与它自己两条护栏冲突 （"保持 I/II 类证据分离"、"不要在没有显式归一化时混用 %rank、IC50、概率和模型分"）： class1 来自 IC50、class2 来自 %rank， 然后 presentation = max(class1, class2)。
  • I 类打分用的是原始 nM 而不是 %rank。不同等位基因的亲和力分布差别很大， %rank 存在的理由正是纠正这一点；跨六个等位基因按 nM 排序会系统性偏向那些绝对结合更紧的。
  • 它的基准无法评估它自己的模型。benchmark() 只对 CSV 里 已有的预计算列打分，从不把自己的综合分跑到那些肽上—— 所以这个基准在结构上回答不了"这个包的排序有效吗"。本节上面那张表就是补上的这一评估。
  • 密码子"优化"是每个氨基酸一个固定密码子。所有 Ala 都是 GCC、 所有 Leu 都是 CTG；它随包发布的构建体 GC = 0.6816， 而 QC 只报这个数字、不标红、没有修复循环，也不查限制酶位点、隐蔽 polyA 或剪接基序。 本包按人类密码子使用频率抽样再修复（demo 构建体 GC 52.0%，QC 通过）。
  • Track B 跑在编造的序列上。这一点它自己标注了 （synthetic_functional_fixture）。但值得说具体： 48 条 wt_context 里有 0 条能在人类参考蛋白组中找到， 包括那条标着 BRAF p.K101I 的。所以功能演示验证的是管道通不通， 不是"突变到蛋白上下文"这一步。

两边独立收敛到的设计

25-mer 小基因、突变居中；≤34 个抗原；每基因上限；HLA 覆盖加成；贪心组合选择； 表达 / 克隆性 / 自身相似性作为分开的轴；明确拒绝声称复现 V940； RUO 框架并列出缺失的 CMC 要素。这些两边都各自做了—— 说明它们更像是被问题本身逼出来的，而不是口味问题。

08

真实患者还需要补什么

按影响从大到小。

  • 正常样本的四位 HLA 分型（OptiType / xHLA / HLA-HD）。绝不能用肿瘤样本做分型——HLA 位点的 LOH 会把结果带偏。这是单一最大误差来源。
  • 转录本级 TPM 与 RNA 层面的突变等位基因比例。后者能抓到被无义介导降解或等位失衡沉默掉的突变，这是基因级 RSEM 看不见的。
  • 片段级拷贝数 + ABSOLUTE/FACETS 纯度，让 CCF 从估计变成测量。
  • II 类预测真的跑起来（需要 II 类分型）。CD4 帮助不是可选项——最早的 mRNA 新抗原疫苗反应主要就是 CD4 的。
  • 移码 / 新读框与融合新抗原的转录本级注释。黑色素瘤里这只是一小部分；在 MSI-H 肿瘤里，好候选大多出在这里，不能跳过。
  • 患者自身肿瘤的质谱免疫肽组。这一步能把呈递从 unverified 变成 computed。

该有的心态

已发表的前瞻性比较（TESLA 联盟对多条新抗原预测流水线的盲法评估）显示， 排名靠前的预测新抗原真正被患者 T 细胞识别的比例在百分之十几到二十几， 各条流水线都是如此。任何对一份 34 肽载荷表现出接近确定性的说法都是过度声称—— 包括这一条。排序让 34 个名额花得比随机好得多，最终读数仍然是患者的 T 细胞。
